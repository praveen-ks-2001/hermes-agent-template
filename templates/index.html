Upload it via Restore below on another deployment to reproduce this bot there. The file is not encrypted — it contains your API keys and bot tokens in plain text, so store it somewhere safe.

Uploading a backup here overwrites this deployment's current config, credentials, and data with the backup's contents, then briefly restarts the gateway. Anything changed here since the backup was taken (e.g. newer user approvals) can be lost. A safety snapshot of the current state is taken automatically first — see below if you need to recover it.

How to Setup
Get your Hermes Agent running in minutes
1 Get a Free LLM API Key
  1. Go to openrouter.ai and create a free account.
  2. Once logged in, go to openrouter.ai/workspaces/default/keys and click Create Key. Copy the generated API key — it starts with sk-or-...
  3. OpenRouter offers many models, including free ones. To get started, you can pick a free model such as: nvidia/llama-3.3-nemotron-super-49b-v1:free Browse all available models at openrouter.ai/models — filter by "Free" to see no-cost options.
  4. Head over to the Setup page (left sidebar), select OpenRouter as provider, paste your API key, and enter the model name. Want a different provider (Anthropic, DeepSeek, Groq, Cerebras, Mistral, etc.)? Open the Hermes Dashboard from the sidebar — the Keys tab lists every provider Hermes supports out of the box, plus skills, toolsets, and analytics you can configure from there.
2 Connect a Messaging Platform

Hermes Agent can work through messaging platforms. Connecting one is optional — the easiest to set up is Telegram.

  1. Open Telegram and search for @BotFather.
  2. Send /newbot and follow the prompts — give your bot a name and username.
  3. BotFather will reply with a Bot Token — it looks like 1234567890:ABCdefGhIjKlMnOpQrStUvWxYz. Copy this token.
  4. Go to the Setup page, enable Telegram under Messaging Channels, and paste the Bot Token.
  5. For Allowed User IDs, if you're just starting out, enter * to allow all users. You can restrict access later by specifying individual Telegram user IDs.
  6. Click Save & Start on the bottom right — your Hermes Agent is now live!
Facing an issue or something not working as expected? Create a GitHub issue and we'll help you out.
What's New
Changes and updates to this template
main always ships the latest release — that is what you get by default. To stay on, or roll back to, a particular Hermes version, point your Railway service at that release's branch and redeploy.
Release branches are named release/<hermes-version>/<n>. /1 is where that Hermes version first landed; /2, /3 and so on are template-only fixes and improvements on top of it — the Hermes version never changes within a series. Pick the highest number for the Hermes version you want; each branch stays put once published.
September 6, 2026
Git branch release/v2026.8.31/1 Hermes compatible version v2026.8.31
Hermes update
  • Updated Hermes Agent to v2026.8.31 (from v2026.8.27). Three more AI providers — Tencent TokenPlan, Ramp Router and Nebius — are available from the Hermes Dashboard → Keys tab, and Kanban boards can now be exported and imported.
  • Scanned PDFs can be read now. If you have a Firecrawl key saved, pages that are just images of text get sent for OCR instead of coming back empty.
  • Messaging the bot while it is still answering gets a reply. Hermes used to hold that message silently for up to 30 minutes; it now tells you within a few seconds to resend once the current answer is finished.
  • Connecting a Claude Pro/Max subscription moved out of the dashboard. Hermes removed that button for policy reasons. Open the Chat tab's terminal and run hermes auth add anthropic instead — plain Anthropic API keys are unaffected.
Changes to support upstream updates
  • Reading PDFs and Office files keeps working. Hermes made its document reader a built-in part of the package. This template used to install its own copy on top, which would now replace it with an older version Hermes then refuses to use — every PDF, Word, Excel and PowerPoint read would have failed on every deploy, retrying silently in the background forever. The extra copy is gone.
  • Tavily search was removed from Hermes, so Setup offers Keenable instead. If you had picked Tavily as your search engine in the Hermes Tools tab, pick another one there — searches error until you do. Any Tavily key you saved is left untouched, just unused.
  • Restarting waits for the bot to finish writing to disk. Hermes now takes longer to shut down when a scheduled job is running, and we were cutting it off part-way — something Hermes itself now documents as a cause of database corruption.
  • Temporary files stay out of your storage. Hermes moved the bot's command scratch space onto your data volume; it is back in the container's temporary space, so backups stay small and a restore can't be blocked by leftovers.
Bug fixes
  • Switching profiles from the Chat terminal no longer hijacks the bot. Running hermes profile use could quietly move the bot and the dashboard onto that profile at the next restart, so your approved users and settings appeared to vanish while the bot kept running as someone else.
  • Dashboard sign-in keys saved into the config file can no longer lock you out. If they ever landed there — through a restore or the Keys tab — every Hermes page showed a sign-in error until a redeploy. They are now removed automatically at startup.
  • A broken configuration no longer restarts in a loop. When the bot cannot start because of a settings problem, the gateway now stops and says so plainly instead of retrying the same failure five times.
August 29, 2026
Git branch release/v2026.8.27/1 Hermes compatible version v2026.8.27
Hermes update
  • Updated Hermes Agent to v2026.8.27 (from v2026.8.13), covering five upstream releases. Eleven more AI providers are available from the Hermes Dashboard → Keys tab, and everything you had configured keeps working unchanged.
  • Helper agents work harder by default. When the bot splits a task into helpers, Hermes raised both how many steps each helper may take (50 → 250) and how many run at once (3 → 10). Both are Hermes' own new defaults, left as-is. The step limit only changes for brand-new deployments, but the parallel limit applies to everyone straight away — so a busy bot can do more at once, and spend more with your provider.
Changes to support upstream updates
  • The Hermes dashboard keeps working — and MCP tool sign-ins now work too. Hermes now treats a deployment that advertises a public web address as one that must have its own password, and shuts the dashboard down at startup when it doesn't. On Railway that address is filled in automatically, so Chat, Keys, Kanban and every other Hermes page would have shown “Dashboard unavailable” on every deploy — while this admin panel and the health check stayed perfectly green. That same address is what Hermes uses to send you back after approving an MCP tool login, so simply dropping it would have quietly broken those. Instead, the Hermes dashboard now has its own password — set automatically from your admin login — and this template signs in for you behind the scenes. You still sign in once, exactly as before.
  • The sign-in page moved to /setup/login. Old links still work. If you had bookmarked the login page directly, it will redirect you.
  • Restoring a backup works again. Hermes started leaving three more folders out of backups. Our safety check didn't know that and could refuse a perfectly good archive with “couldn't create a complete safety snapshot”, blocking the restore entirely.
  • The bot can no longer switch itself off. Hermes relaxed the rule that stopped the agent shutting down its own gateway, so a stray instruction could take the bot offline. This template now identifies itself as the supervisor, which restores the block.
  • Scheduled jobs finish before a restart. Hermes now waits for a running scheduled job to complete when shutting down. We were cutting it off too early, killing the job halfway and leaving it stuck as “running”.
  • Leftover lock files are cleared on boot, so a new safety check in Hermes can't leave the bot unable to restart.
Improvements
  • A mistyped OpenRouter key is caught before you save. Hermes now ignores any OpenRouter key that doesn't begin with sk-or-, without showing an error anywhere — the bot simply never replies. Setup now warns you the moment the pasted key can't work.
August 15, 2026
Git branch release/v2026.8.13/1 Hermes compatible version v2026.8.13
Hermes update
  • Updated Hermes Agent to v2026.8.13 (from v2026.8.3) — adds a community plugin catalogue, review workflows on the Kanban board, and a new Actual Computer provider, now selectable in Setup.
  • Fewer out-of-memory restarts. Hermes now reads the memory limit your Railway plan gives the container and drops the oldest cached conversations before it hits it, instead of being killed and restarted.
  • Reading PDFs and Office files works. Send the bot a PDF, Word, Excel or PowerPoint file and it can now read the contents. The reader is built into the image, so it works on the first try and keeps working after every redeploy.
Changes to support upstream updates
  • A paused bot is now visible. Hermes added a /pause command that any paired user can send. It silences the bot completely while Status still showed “running” and health checks still passed — and because it is stored on the disk, redeploying did not clear it. Status now shows a clear Paused banner with a Resume button.
  • Browser tools left as they were. Hermes switched to a new browsing engine by default whenever a particular tool is present on the machine — which it is here, by coincidence of the base image. That would have handed the bot a browser tool that cannot work in this container. Pinned to the previous behaviour, so nothing changes for you.
  • Clearer message when a backup collides. Hermes now refuses to run two backups at once. A restore that hit this reported “the backup command failed”, which reads like data loss; it now says another backup is running and nothing was changed, so you can simply retry.
  • Backups are checked more thoroughly. The completeness check previously only looked for the conversation database; it now verifies every database on your volume is present before a backup is accepted as a safe restore point.
Bug fixes
  • Restoring a backup can no longer take the dashboard down permanently. One setting, if present in a restored backup, made Hermes shut its own dashboard down seconds after start with no way back except a redeploy. It is now stripped automatically on startup and after any restore.
  • Leftover files from interrupted backups are cleaned up instead of accumulating on your volume.
August 8, 2026
Git branch release/v2026.8.3/1 Hermes compatible version v2026.8.3
Hermes update
  • Updated Hermes Agent to v2026.8.3 (from v2026.7.20, covering two upstream releases) — adds video generation tools, the Vercel AI Gateway and Vertex providers, outbound webhooks, and gateway health monitoring.
  • Fewer out-of-memory restarts — Hermes now returns unused memory to the system as it runs, which directly targets the crashes that hit long-running bots.
  • An interrupted message is retried automatically. If your bot is killed mid-answer (an out-of-memory crash, or a redeploy), Hermes now re-runs that message when it comes back instead of losing it. Left enabled — but if the message asked for something with real-world side effects, it will be carried out a second time.
Changes to support upstream updates
  • Restart no longer parks the bot. Hermes changed /restart to wait for the current task to finish first — up to six hours — and during that wait the bot stays online, shows as healthy, and refuses every message. Restored to restarting straight away, as it did before.
  • Long replies and large output no longer cut the Chat tab. Hermes raised its WebSocket message limit to 384 MB while this proxy still stopped at 1 MB, so anything bigger silently dropped the connection mid-message with no error anywhere. Both ends now match.
  • Unexpected restart during very heavy tasks. Hermes added a watchdog that restarts the gateway if it stops responding for about two minutes. Kept on — this template already restarts the gateway cleanly — but a genuinely heavy task can now end in a restart rather than a reply.
  • Build pinned against upstream's new checks. Hermes now fails the build outright on the wrong Node.js version and blocks non-editable installs; both are pinned and documented so a future change can't quietly break the image.
Improvements
  • The "this won't survive a redeploy" notice now also covers the Tools tab. Installing a toolset from the dashboard wipes on the next deploy just like a memory provider, but used to warn you about neither — only the provider button did. Both now warn, and re-installing still restores everything, since your settings and keys live on the volume.

July 27, 2026
Git branch release/v2026.7.20/1 Hermes compatible version v2026.7.20
Hermes update
  • Updated Hermes Agent to v2026.7.20 (from v2026.7.1) — adds the new Hermes Console, session export, and three new providers: Fireworks AI, DeepInfra and Upstage Solar.
Changes to support upstream updates
  • Hermes Console. Hermes added a new console connection; this template only forwards connections it explicitly knows about, so the button failed. Added it to that list.
  • Restart throttling. Hermes added its own restart brake that paused the gateway before starting it — on top of the one this template already has. Turned Hermes' off so only ours applies; saving settings repeatedly no longer takes the bot offline.
  • Backups. Hermes can now leave your chat history out of a backup while still reporting success. The template now checks the file itself: a restore is refused unless its automatic safety snapshot is complete, and downloads warn instead of quietly handing you a partial file.
  • Paired users. Hermes now re-copies old pairing data on every start, which brought revoked users back. The template merges the old and new locations into one after a restore, so a revoke stays revoked.
  • Long replies. Hermes stopped sending keep-alive pings on its internal connection; this template was still expecting them and cut Chat off mid-reply. Matched Hermes' behaviour.
  • MCP sign-in. Hermes builds its return address from the web address it sees, which is internal behind this template's proxy. The template now tells Hermes its real public URL.
  • Memory providers. Hermes added a button that installs software into the running container, with no check for immutable deployments. The template now warns first — anything installed this way is lost on the next deploy.
  • Conversation auto-reset. Hermes changed its default, which would have made newly created deployments behave differently from existing ones. The template now sets it explicitly so both match.
Bug fixes
  • Fixed the Users tab reading the wrong location after a restore — pairing requests could be invisible and approvals ignored until the next restart.
  • Gateway shutdown now waits longer, so several connected chat platforms can disconnect cleanly instead of being cut off.
